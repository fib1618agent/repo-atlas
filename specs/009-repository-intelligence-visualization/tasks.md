# Tasks: Repository Intelligence Visualization

**Input**: `specs/009-repository-intelligence-visualization/` (spec, plan, research, data-model, contracts, quickstart, checklist)

**Tests**: included (bun unit + integration; UI state rendering; opt-in real-data; browser acceptance).

**Format**: `- [ ] T### [P?] [US?] Description`, then indented `Purpose`, `Files`, `Requirements`, `Depends`, `Verify / Completion`. **[P]** = different files, no ordering dependency. A task is complete only when its Verify condition is met and recorded; writing code is not completion.

## Ground rules for every task

- **Read-only and additive**: no writes, no queue sends, no snapshot acquisition, no new table/index/dependency (FR-010, FR-018). Do not modify Feature 001/002/004/005/007 files, `.env.example`, `package.json`, lockfiles, `sources-store.ts` or existing stores.
- **Only two edits to existing components** (one additive entry link each): `RepositoryPanel.tsx` and `catalogue.tsx`. `routeTree.gen.ts` is regenerated by the router plugin, never hand-edited.
- **No fabricated intelligence**: no relationship, edge or execution-path data or copy (FR-008/FR-009).
- **Local-first**: no Cloudflare, Wrangler, deployment or live operation. Local emulation (D3(b)) needs separate user authorization.
- **Real data**: acceptance uses `imdadareeph` and `fib1618agent/repo-atlas`; fixtures only for deterministic unit tests.
- Unrelated working-tree changes (AGENTS.md, docs/AGENT-GOVERNANCE.md, roadmap.md, Query-cache experiment files, `.claude/skills/gitnexus/`, `.playwright-mcp/`) are never staged or altered.
