## "One file per invocation" — REPO-BEHAVIOR verdict

**NO — the current repository does not establish "one file per invocation"; the code establishes the opposite shape for Feature 002's consumer.**

Evidence:
1. `symbol-worker.ts:113-132` fetches a page of up to `extractionBatchSize` files (default 50, `config.ts:10`) and calls `extractFile` for every file in the page inside one `processSymbolQueueMessage` call.
2. `plugins/cloudflare-symbol-queue.ts:34-41` runs `processSymbolQueueMessage` for every message in the delivered batch inside one hook call (one dispatch per `queue()` call, `_module-handler.mjs:51-58`).
3. Nothing in `src/` or `plugins/` sets the extraction unit to one file, and nothing sets the delivered batch to one message (`wrangler.toml:42` = 10 max; `max_batch_timeout` unset).

Not claimed: that a batch of 10 full 50-file messages ever occurs; the runtime batch size and page fill are UNKNOWN (row 2/row 4).

Documentation statements that use the word "unit"/"invocation" (kept out of the evidence rows; they describe design intent, not behaviour): `specs/002-ast-symbol-intelligence/plan.md:81` ("one ExtractionJob unit per invocation") — here *unit* means a bounded file batch, consistent with the code; `symbol-worker.ts:78-83` comment ("One `ExtractionJob` unit per invocation (bounded file batch, …)") — the comment says one unit per invocation, but the plugin loop (row 2) delivers as many messages as the batch contains, so this comment is **not** confirmed by the hook code (CONTRADICTION between comment and plugin loop, recorded, not reconciled).
